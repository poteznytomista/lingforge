LINUX / v0.1.0

Your first launch.

LingForge 0.1.0 is an experimental Linux x86_64 AppImage. It was tested on Arch Linux; compatibility with every Linux distribution is not established. Windows downloads are not yet available.

Open the application

Download the AppImage, allow it to execute using your file manager’s permissions control, and open it. You do not need Rust, Node.js, npm or the source code. Your desktop still needs compatible Linux libraries and graphics support. Some distributions need FUSE 2 compatibility; keep existing FUSE 3 components intact.

From the directory containing the download:

chmod +x LingForge_0.1.0_amd64.AppImage
./LingForge_0.1.0_amd64.AppImage

A blank window on NVIDIA

The tested NVIDIA machine needs this WebKit rendering workaround:

WEBKIT_DISABLE_DMABUF_RENDERER=1 ./LingForge_0.1.0_amd64.AppImage

This applies to that launch only. It has not been established as necessary on other machines.

Launching from VS Code’s Snap terminal

Incompatible inherited GTK/GIO lookup paths interfered with native testing. The successful launch removed them for the application process: 

env -u GIO_MODULE_DIR -u GTK_PATH -u GTK_EXE_PREFIX -u GDK_PIXBUF_MODULE_FILE WEBKIT_DISABLE_DMABUF_RENDERER=1 ./LingForge_0.1.0_amd64.AppImage

Native automation additionally used GDK_BACKEND=x11 under KDE Wayland. File-manager launch and other display configurations still need broader acceptance testing.

Check the download

The checksum identifies the tested file; it is not a digital signature. Compare the output of: 

sha256sum LingForge_0.1.0_amd64.AppImage

Expected SHA-256:

793260508f582463b3b9e4e331e38f50fd065b786736076471ab933dec9c6408

Download the checksum file.

Start with a disposable project

Choose New language and a parent folder you can write to. LingForge creates a project folder there. Save explicitly with the editor’s Save button or Ctrl+S. Keep your language folders separate from the AppImage.

Export a full project archive to back up or transfer saved work. Do not copy the database alone while the app is using it. Recovery creates a new copy. A forced shutdown can lose unsaved drafts; snapshots and undo are different mechanisms.

Current boundaries

The Linux build passed 34 bounded native checks. Full desktop workflow acceptance, real input-method composition, advanced drawing/shaping and Windows remain unfinished. Writing, documents, grammar, fonts and rules are experimental. Resources and PDF export are not available. Use independent archives for anything important.
