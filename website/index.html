BEFORE THE FIRST WORD.

A few things
worth knowing.

How do I run the AppImage?

Allow the downloaded file to execute in your file manager, then open it. You need a compatible Linux x86_64 desktop; some systems need FUSE 2 compatibility. No Node.js or Rust installation is required.

On the tested NVIDIA system, use this command from the download folder to avoid a blank window: 

chmod +x LingForge_0.1.0_amd64.AppImage
WEBKIT_DISABLE_DMABUF_RENDERER=1 ./LingForge_0.1.0_amd64.AppImage

Inside a VS Code Snap terminal, inherited GTK/GIO paths may also interfere. See the complete Linux launch notes.

Can I trust it with my main language project?

Begin with disposable work. Automated checks and bounded Linux workflows have passed, but complete native acceptance is still in progress. Keep independent exported archives of anything important. Snapshots contain saved data; unsaved drafts and undo history do not survive a forced shutdown.

Does it work with my invented script?

You can create stable characters, import or draw constrained vector outlines, map input and build experimental fonts. General bidirectional paragraphs, vertical text, complex-script document layout and full IME acceptance are not complete. The font lab’s single-run RTL option is not full bidi document support.

Where are my files stored?

You choose a parent folder when creating a project. LingForge stores the project database, manifest and snapshots in its own folder there. The AppImage is separate from your data. Use a project archive to transfer saved work; do not copy an active database file by itself.

What about Windows and macOS?

Linux and Windows are the project’s targets. This release offers a tested Linux AppImage only. Windows builds and installer acceptance are unfinished; macOS is outside the current scope.
