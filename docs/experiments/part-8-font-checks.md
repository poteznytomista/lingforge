## Deferred automated checks

Run the ordinary frontend and Rust workspace checks after authorization. The new `lingforge-font` tests parse generated TrueType, compare cmap/metrics/license fields, verify whole-font checksum and determinism, exercise context substitution/ligature source intervals, compare mark offsets and RTL cluster order, test supplementary PUA/empty runs, and reject unsupported independent painted paths and coordinate overflow. Run against the pinned compiler/geometry/shaper libraries; resolve actual failures rather than assuming APIs from static review are sufficient.

The core/storage tests exercise schema 6 → 7 migration and snapshots; no-op saves; both source/profile revisions; protected character/variant/script deletion; profile identity through glyph edits, archive transfer, reopen and recover-as-copy; backup/transaction failures; corrupted references; and no-clobber font publication. Earlier migration fixtures remove the new table before their historical downgrade. Browser/component test source covers source selection/undo, preview invalidation, hidden-page mapping validation, invalid text retention, FontFace rejection/disposal and obsolete loads, failed-save retention, navigation guards and cancelled export. These synthetic tests do not validate a real webview's font engine.

## Native experiment sequence

1. On **Linux/WebKitGTK** and separately **Windows/WebView2**, create a disposable project. Author the five fixture designs under Writing systems (one path with multiple contours where needed), save, then open Fonts & shaping. Compare proposed mappings and shared metrics; add unencoded variants, base/mark anchors, one context rule and one ligature rule. Save/restart/reopen and compare the complete profile and all IDs.
2. Build previews for an empty sample, individual bases, a context match/nonmatch, overlapping contexts, ligature matches with differing lengths, base+mark, repeated marks, missing/removed mappings and the same source sequence in LTR/RTL. Verify diagnostics where the model forbids an operation. Record reference glyph IDs, ranges, offsets and advances separately from screenshots of platform output.
3. Select complete and partial ligature/source ranges. Use click/Shift-click, numeric boundaries, keyboard movement, deletion and undo/redo. Select/copy the readonly platform run; compare encoded Unicode with the source IDs and confirm the loss disclosure. Exercise focus, narrow windows, large text, high DPI, forced colors and reduced motion. Test actual OS selection/clipboard/IME behavior in the earlier document editor too; this lab does not replace that gate.
4. Compare real Unicode combining marks with PUA-mark assignments. Inspect normalization, zero advance, base anchors, font load failure and fallback behavior. Confirm FontFace entries are removed after rebuilding, switching profiles, navigation and session change, including load promises that finish after disposal. Check responsiveness near glyph, point, rule, sample and font-byte bounds.
5. Compare SVG and font contours at large zoom: holes/opposite winding within one path, implicit closure, multiple subpaths, drawing after Close, negative coordinates, quadratics, cubic subdivision and integer rounding. Multi-path rejection must retain source/draft data. Test shared source em/baseline settings and transformed coordinate/side-bearing overflow. Verify source strings are never rewritten by build/export.
6. Exercise Ctrl+S, profile switching, native close, failed backup/save, stale source/profile revisions, disk-full/read-only targets, cancelled native pickers and existing export names. Keep pending drafts on failure and require explicit deletion of a profile before removing its source script. Change a glyph outline without changing IDs and rebuild; existing documents/profile samples must retain their original character identities.
7. Export new TTF filenames for each embedding policy after entering fixture license/copyright. Inspect cmap, glyf/loca, head/hhea/hmtx, maxp, OS/2, name, post and layout tables. Check deterministic bytes for identical inputs, full-font/table checksums and strict font-sanitizer results. Inspect BMP and supplementary mappings, non-ASCII family text and name-table limits.
8. On each OS, open/install only disposable fixture fonts in an isolated test account as appropriate. Compare a local browser and an independent text application such as LibreOffice. Verify PUA entry, feature availability, baseline/line spacing, marks, glyph-cache replacement, font naming and uninstall. Installation and existing font replacement are manual validation steps, not LingForge app actions. Record application versions and exactly which feature works; do not infer broad compatibility from one parser or screenshot.
9. Transfer the full project archive Linux → Windows → Linux, regenerate the same font, and compare source identities/profile/geometry and output bytes. Recover a backup into a new copy. Test malformed profile JSON, duplicate/unknown mappings, dangling variants and supported older schemas. Never overwrite originals while recovering.

Optional validation tools: fontTools/TTX (Python 3 plus its package), a font sanitizer, HarfBuzz's `hb-shape`, Linux fontconfig inspection tools, and an independent document app/PDF viewer for later export research. They are **not application dependencies** and have not been installed. Choose/pin exact verification versions when execution is authorized. Existing browser/native-driver tools remain as documented for Part 1.
